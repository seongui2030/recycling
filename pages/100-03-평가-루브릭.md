# 100-03. 평가 루브릭

> **코드 양보다 과정과 설명을 평가합니다**

| 평가 영역 | 우수 | 보통 | 시작 |
|---|---|---|---|
| 문제 정의 | 사회문제와 서비스가 명확히 연결됨 | 연결을 설명함 | 설명이 부족함 |
| 컴퓨터 비전 | 데이터·라벨·검출을 설명함 | 일부 설명 가능 | 용어가 낯섦 |
| 데이터베이스 | 테이블과 관계를 설명함 | 테이블을 확인함 | 저장 구조를 이해하기 어려움 |
| 웹/API | 브라우저-서버 흐름 설명 | 기본 흐름 이해 | 구분이 어려움 |
| 로그인 | OAuth와 세션을 설명 | 로그인 성공 | 설정에 도움 필요 |
| 배포 | Vercel까지 완성 | 배포 성공 | 배포 과정 도움 필요 |
| AI 윤리 | Human-in-the-loop를 설명 | 오류 가능성 인식 | AI를 정답으로만 생각 |
| 발표 | 서비스의 의미와 한계를 설명 | 기능 설명 | 기능 시연 중심 |

### 교사에게 권하는 평가 질문

- “AI가 틀리면 어떻게 하나요?”
- “왜 사람이 숫자를 수정할 수 있나요?”
- “왜 Roboflow API Key를 `VITE_`로 만들지 않았나요?”
- “왜 `donations`와 `donation_items`를 나누었나요?”

이 질문에 자신의 말로 답하는 학생이라면 코드를 단순 복사한 수준을 넘어선 것입니다.
